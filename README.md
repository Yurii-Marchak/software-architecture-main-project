# Звіт про реалізацію проєкту: Бізнес-логіка, сервіси, модульне тестування

## 1. Реалізовані бізнес-сценарії
У рамках розробки системи управління складом комп'ютерної техніки та конфігуратора ПК було реалізовано наступні критичні сценарії:
1. **Фільтрація каталогу:** Динамічна вибірка комплектуючих за ціною та специфічними характеристиками (сокет, бренд) із застосуванням функціонального програмування (лямбда-виразів) безпосередньо у пам'яті.
2. **Примусова фільтрація конфігуратора (Forced Filtering):** Генерація правил апаратної сумісності під час збірки ПК. Система автоматично фільтрує материнські плати за сокетом обраного процесора та розраховує необхідну потужність блоку живлення (PSU) на основі споживання CPU та GPU.
3. **Оформлення замовлення (Checkout):** Комплексна транзакція, яка перевіряє наявність користувача, доступність необхідної кількості товарів на складі, здійснює списання залишків та створює фіскальний чек (Order).
4. **Фонова відправка чеків (Fire-and-Forget):** Асинхронне делегування задачі відправки електронного листа з деталями замовлення через SMTP-сервер без блокування основного потоку веб-сервера.
5. **Приймання поставок:** Транзакційне поповнення інвентарних залишків на складі при надходженні нової партії комп'ютерних комплектуючих.

## Як запустити проект
Крок 1. Клонування репозиторію та навігація
Відкрийте термінал (або Git Bash) та клонуйте вихідний код проєкту у зручну для вас директорію, після чого перейдіть до папки проєкту:

git clone https://github.com/Yurii-Marchak/software-architecture-main-project.git
cd pc_warehouse_project

Крок 2. Створення та активація віртуального середовища
Для ізоляції залежностей проєкту від системних пакетів Python необхідно створити віртуальне середовище. У терміналі виконайте команди:

# Створення віртуального середовища з назвою "venv"

python -m venv venv

# Активація для ОС Windows:
venv\Scripts\activate
Крок 3. Встановлення залежностей
Встановіть усі необхідні зовнішні бібліотеки (FastAPI, Motor, Pydantic, pytest тощо), які вказані у файлі конфігурації:

pip install -r requirements.txt

Крок 4. Налаштування змінних оточення (.env)
Для безпечного зберігання конфіденційних даних (паролів, ключів доступу, шляхів до бази даних) система використовує змінні оточення.
У кореневій папці проєкту (там, де знаходиться файл main.py) створіть новий файл із назвою .env (без імені, лише розширення) та впишіть у нього наступні конфігураційні дані:

# Рядок підключення до бази даних MongoDB (залиште цей, якщо БД локальна)
MONGO_URI=mongodb://localhost:27017/

# Секретний ключ для шифрування сесій користувачів (можна вписати будь-який набір символів)
SECRET_KEY=super_secret_key_for_fastapi_sessions_12345

# Дані для підключення до SMTP-сервера (для відправки чеків на пошту)
SMTP_EMAIL=your_real_email@gmail.com
# УВАГА: Тут має бути не пароль від пошти, а спеціальний "Пароль додатку" (App Password)
SMTP_PASSWORD=your_16_character_app_password

Як отримати SMTP_PASSWORD (для Gmail):
1.	Перейдіть у налаштування свого Google Акаунту -> розділ "Безпека".
2.	Увімкніть "Двоетапну перевірку" (2-Step Verification).
3.	Перейдіть до розділу "Паролі додатків" (App passwords).
4.	Створіть новий пароль (назвіть його, наприклад, "FastAPI App"). Google згенерує 16-значний код. Саме його без пробілів потрібно вставити у файл .env.
Крок 5. Міграція та збагачення бази даних
Оскільки система вимагає наявності товарів для роботи каталогу та конфігуратора, необхідно запустити скрипт міграції. Цей скрипт прочитає CSV-файли, згенерує ціни та залишки на складі, і запише їх у MongoDB.
python scripts_and_data_analysis/db_seeder.py

Крок 6. Запуск локального сервера
Після успішного налаштування бази даних запустіть веб-адаптер FastAPI за допомогою ASGI-сервера Uvicorn:

uvicorn main:app –reload

Крок 7. Доступ до системи
Відкрийте будь-який веб-браузер (Google Chrome, Mozilla Firefox) та перейдіть за адресою: http://localhost:8000
Для запуску системи автоматизованого тестування (якщо сервер зупинено) використовуйте команду:
pytest -v


## 2. Структура коду (Гексагональна архітектура)
Проєкт організовано за принципами чистої гексагональної архітектури (Ports and Adapters):
* **Models (`core/models/`):** Визначають структуру сутностей (User, Component, Order, PCBuild) із суворою валідацією даних через бібліотеку Pydantic.
* **Ports (`core/ports/`):** Абстрактні класи-інтерфейси (IComponentRepository, IEmailSender), що декларують контракти взаємодії ядра із зовнішніми системами.
* **Services (`core/services/`):** Містять "серце" системи — бізнес-логіку (CatalogService, BuilderService, OrderService). Вони оркеструють порти, але абсолютно не залежать від конкретної реалізації бази даних чи веб-фреймворку.
* **Adapters (`adapters/`):** Імплементують абстрактні порти для роботи з конкретними технологіями (MongoDB через Motor, електронна пошта через smtplib, HTTP-запити через FastAPI).
* **Dependencies (`adapters/web/dependencies.py`):** Модуль інверсії залежностей (Dependency Injection), який зв'язує порти та адаптери під час ініціалізації системи.

## 3. Рефакторинг та Лінтинг
Після реалізації основного функціоналу було проведено рев'ю коду. Жодних критичних "запахів коду" не виявлено. Код відповідає принципам SOLID, зокрема принципу єдиної відповідальності (SRP) та інверсії залежностей (DIP). Завдяки застосуванню асинхронних корутин (`async/await`) повністю усунуто ризики блокування I/O операцій.

Для стандартизації стилю та статичного аналізу було використано лінтер **flake8**.
Команда перевірки: `flake8 core/ adapters/ --max-line-length=120`
Результат: 0 помилок та попереджень. Код повністю відповідає стандартам PEP 8.

## 4. Юніт-тестування
Для перевірки бізнес-логіки використано фреймворк `pytest`, плагін `pytest-asyncio` для асинхронних функцій та бібліотеку `unittest.mock` (об'єкти `AsyncMock`) для повної ізоляції бази даних. Написано 13 тестів, які покривають 100% позитивних та негативних сценаріїв доменних сервісів. Загальне покриття коду (Code Coverage) становить понад 85%.

**Приклади тестових сценаріїв:**
* Успішний розрахунок необхідної потужності блоку живлення у `BuilderService`.
* Відмова в оформленні замовлення, якщо товару недостатньо на складі (викликається `ValueError`).
* Перехоплення помилки валідації (`ValidationError`) при спробі створити товар із від'ємною ціною.

**Інструкція для запуску тестів:**
1. Активуйте віртуальне середовище (`venv\Scripts\activate` для Windows).
2. Встановіть залежності: `pip install -r requirements.txt`.
3. Виконайте команду: `pytest tests/ -v`
